Tables in schema "public" (from Supabase; RLS enabled on all)
--------------------------------------------------------------
1) profiles
   - id (uuid, PK), full_name, role (worker|verifier|advocate), city_zone, created_at
   - id references auth.users(id)
   - Referenced by: earnings.worker_id, grievances.worker_id

2) earnings
   - id (uuid, PK), worker_id → profiles.id, platform, date, hours_worked, gross_earned,
     deductions, net_received, screenshot_url, status (pending|verified|flagged),
     anomaly_explanation, created_at

3) grievances
   - id (uuid, PK), worker_id → profiles.id, platform, category, description,
     status (open|escalated|resolved), tags (text[]), created_at

5) community_posts (worker bulletin / 4th persona)
   - id, author_id → profiles.id, title, body, platform, category, tags (text[]),
     status (pending|visible|hidden|removed), moderator_note, created_at, updated_at

4) market_benchmarks
   - id (uuid, PK), platform, city_zone, avg_hourly_pay, avg_deduction_rate, created_at

Local services (default ports — override with .env)
----------------------------------------------------
Node (service-grievance-node), default PORT=5000:
- Root JSON:        http://localhost:5000/
- Health:           http://localhost:5000/health
- Downstream probe: http://localhost:5000/services/health
- Auth:
  - POST http://localhost:5000/api/v1/auth/signup   (email/password; optional full_name, city_zone)
  - POST http://localhost:5000/api/v1/auth/login    (returns session; use access_token as Bearer)
  - GET http://localhost:5000/api/v1/me             (Bearer = Supabase user access_token)
  - GET http://localhost:5000/api/v1/verifier/ping  (role: verifier only; requires Bearer)
- Swagger UI:       http://localhost:5000/api-docs
- OpenAPI file:     `service-grievance-node/docs/openapi.yaml` (also served at `/openapi.yaml` and `/openapi.json`)
- Data APIs need `Authorization: Bearer <access_token>`: `/api/grievances`, `/api/analytics/...`, `/api/certificates/...`, `/api/community/...` (see Swagger tag **Community**)

Python — Earnings (service-earnings-python), default PORT=8000:
- Swagger / docs:   http://localhost:8000/docs
- ReDoc:            http://localhost:8000/redoc

Python — Anomaly (service-anomaly-python), default PORT=8001:
- Swagger / docs:   http://localhost:8001/docs
- ReDoc:            http://localhost:8001/redoc

Frontend (when added; Vite default):
- http://localhost:5173
- Copy `frontend/.env.example` → `frontend/.env` — use `VITE_API_BASE_URL=http://localhost:5000` only (no direct :8000 / :8001 in the browser).

BFF (Node → Python; same Bearer as `/api/v1/me`)
-------------------------------------------------
All requests use the Node host (e.g. http://localhost:5000) + `Authorization: Bearer <access_token>`.

- Earnings (proxied to FastAPI `/api/v1/...`): `/api/v1/earnings/status`, `/api/v1/earnings/shift-logs`, POST import-csv, PATCH `.../verification`, etc.
- Anomaly: `/api/v1/anomaly/status` (and future `/api/v1/analyze` when implemented in Python).

OpenAPI: tag **BFF Python** in `service-grievance-node/docs/openapi.yaml`; detailed request/response shapes still in Python `/docs` on 8000/8001.

Local wiring (three terminals)
------------------------------
From repo root, only create .env if you do not have one yet:

  test -f service-grievance-node/.env    || cp service-grievance-node/.env.example service-grievance-node/.env
  test -f service-earnings-python/.env   || cp service-earnings-python/.env.example service-earnings-python/.env
  test -f service-anomaly-python/.env    || cp service-anomaly-python/.env.example service-anomaly-python/.env

Then fill Supabase keys in each `.env`. Grievance-node also needs `ANOMALY_SERVICE_URL=http://localhost:8001` and `EARNINGS_SERVICE_URL=http://localhost:8000` (see its `.env.example`).

Terminal A — earnings (8000):

  cd service-earnings-python
  python3 -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
  pip install -r requirements.txt
  uvicorn app.main:app --host 127.0.0.1 --port 8000

Terminal B — anomaly (8001):

  cd service-anomaly-python
  python3 -m venv .venv && source .venv/bin/activate
  pip install -r requirements.txt
  uvicorn app.main:app --host 127.0.0.1 --port 8001

Terminal C — Node (5000):

  cd service-grievance-node
  npm install
  npm run dev

Check downstream reachability (Node probes `GET {base}/health` on each Python base URL):

  curl -s http://localhost:5000/services/health

You want `"reachable": true` for earnings and anomaly when both Python apps are up. Root health on Python: http://localhost:8000/health and http://localhost:8001/health
