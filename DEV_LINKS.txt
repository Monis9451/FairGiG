Tables in schema "public" (from Supabase; RLS enabled on all)
--------------------------------------------------------------
1) profiles
   - id (uuid, PK), full_name, role (worker|verifier|advocate), city_zone, created_at
   - id references auth.users(id)
   - Referenced by: earnings.worker_id, grievances.worker_id

2) earnings
   - id (uuid, PK), worker_id → profiles.id, platform, date, hours_worked, gross_earned,
     deductions, net_received, screenshot_url, status (pending|verified|flagged),
     anomaly_explanation, created_at

3) grievances
   - id (uuid, PK), worker_id → profiles.id, platform, category, description,
     status (open|escalated|resolved), tags (text[]), created_at

5) community_posts (worker bulletin / 4th persona)
   - id, author_id → profiles.id, title, body, platform, category, tags (text[]),
     status (pending|visible|hidden|removed), moderator_note, created_at, updated_at

4) market_benchmarks
   - id (uuid, PK), platform, city_zone, avg_hourly_pay, avg_deduction_rate, created_at

Local services (default ports — override with .env)
----------------------------------------------------
API gateway (service-api-gateway-node), default PORT=5000 — use this host from the browser:
- Root JSON:        http://localhost:5000/
- Health:           http://localhost:5000/health
- Downstream probe: http://localhost:5000/services/health
- Through the gateway (proxied to Node microservices):
  - POST http://localhost:5000/api/v1/auth/signup
  - POST http://localhost:5000/api/v1/auth/login
  - GET/POST/PATCH … `/api/grievances`, `/api/community`, `/api/analytics/...`, `/api/certificates/...` (Bearer required)
- Still on the gateway (not proxied):
  - GET http://localhost:5000/api/v1/me             (Bearer = Supabase user access_token)
  - GET http://localhost:5000/api/v1/verifier/ping  (role: verifier only; requires Bearer)
  - POST … `/api/uploads/...` (shift screenshots; Cloudinary env on gateway)
- Swagger UI:       http://localhost:5000/api-docs
- OpenAPI file:     `service-api-gateway-node/docs/openapi.yaml` (also `/openapi.yaml`, `/openapi.json`)

Node microservices (defaults; set `*_SERVICE_URL` on the gateway to match):
- Auth:          service-auth-node          PORT=5010  `/api/v1/auth`, `/health`
- Grievance:     service-grievance-node     PORT=5011  `/api/grievances`, `/api/community`, `/health`
- Analytics:     service-analytics-node     PORT=5012  `/api/analytics`, `/health`
- Certificates:  service-certificates-node  PORT=5013  `/api/certificates`, `/health`

Python — Earnings (service-earnings-python), default PORT=8000:
- Swagger / docs:   http://localhost:8000/docs
- ReDoc:            http://localhost:8000/redoc

Python — Anomaly (service-anomaly-python), default PORT=8001:
- Swagger / docs:   http://localhost:8001/docs

BFF (Node → Python; same Bearer as `/api/v1/me`)
-------------------------------------------------
All requests use the Node host (e.g. http://localhost:5000) + `Authorization: Bearer <access_token>`.

- Earnings (proxied to FastAPI `/api/v1/...`): `/api/v1/earnings/status`, `/api/v1/earnings/shift-logs`, POST import-csv, PATCH `.../verification`, etc.
- Anomaly: `/api/v1/anomaly/status`, `POST /api/v1/anomaly/analyze`, `GET /api/v1/anomaly/runs` (proxied to Python). Apply `database/anomaly_runs.sql` in Supabase for persisted `run_id` rows.

OpenAPI: tag **BFF Python** in `service-api-gateway-node/docs/openapi.yaml`; detailed request/response shapes still in Python `/docs` on 8000/8001.

Local wiring (recommended: Python first, then Node microservices, then gateway)
-----------------------------------------------------------------------------
From repo root, create `.env` files if missing:

  test -f service-api-gateway-node/.env     || cp service-api-gateway-node/.env.example service-api-gateway-node/.env
  test -f service-auth-node/.env              || cp service-auth-node/.env.example service-auth-node/.env
  test -f service-grievance-node/.env         || cp service-grievance-node/.env.example service-grievance-node/.env
  test -f service-analytics-node/.env         || cp service-analytics-node/.env.example service-analytics-node/.env
  test -f service-certificates-node/.env      || cp service-certificates-node/.env.example service-certificates-node/.env
  test -f service-earnings-python/.env        || cp service-earnings-python/.env.example service-earnings-python/.env
  test -f service-anomaly-python/.env         || cp service-anomaly-python/.env.example service-anomaly-python/.env

Fill Supabase keys in each Node `.env` that talks to the database. The gateway `.env` needs Cloudinary (uploads), `EARNINGS_SERVICE_URL`, `ANOMALY_SERVICE_URL`, and the four `*_SERVICE_URL` entries for Node microservices (defaults in `.env.example`).

Terminal A — earnings (8000):

  cd service-earnings-python
  python3 -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
  pip install -r requirements.txt
  uvicorn app.main:app --host 127.0.0.1 --port 8000

Terminal B — anomaly (8001):

  cd service-anomaly-python
  python3 -m venv .venv && source .venv/bin/activate
  pip install -r requirements.txt
  uvicorn app.main:app --host 127.0.0.1 --port 8001

Terminals C–F — Node microservices (5010–5013), e.g.:

  cd service-auth-node && npm install && npm run dev
  cd service-grievance-node && npm install && npm run dev
  cd service-analytics-node && npm install && npm run dev
  cd service-certificates-node && npm install && npm run dev

Terminal G — API gateway (5000), normal split mode:

  cd service-api-gateway-node
  npm install
  npm run dev

Railway free / few services on the host — one Node process (no extra microservice slots):
------------------------------------------------------------------
From repo root: `npm install` (uses `package.json` workspaces), then start the same gateway
with in-process Node routes:

  INLINE_NODE_SERVICES=1 npm start

(`npm start` at repo root runs `node service-api-gateway-node/server.js`.)
Unset `AUTH_SERVICE_URL`, `GRIEVANCE_SERVICE_URL`, `ANALYTICS_SERVICE_URL`, `CERTIFICATES_SERVICE_URL`
when using this; keep `EARNINGS_SERVICE_URL` and `ANOMALY_SERVICE_URL` for Python.
`/services/health` lists bundled Node domains with `"bundled": true`.

Check downstream reachability (gateway probes `GET {base}/health` on each configured service):

  curl -s http://localhost:5000/services/health

You want `"reachable": true` for Python (earnings, anomaly) and each Node microservice when they are up. Python root health: http://localhost:8000/health and http://localhost:8001/health
